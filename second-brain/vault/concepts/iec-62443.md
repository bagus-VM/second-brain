## One-line Summary
*The international standard series for securing industrial automation and control systems (IACS), covering everything from asset owners to component manufacturers.*

## Core Intuition
Industrial IoT is different from consumer IoT. A compromised smart speaker is annoying; a compromised industrial controller can cause physical harm, environmental damage, or production shutdowns lasting weeks. IEC 62443 recognizes that industrial security requires a holistic approach — it's not just about the device, it's about the entire system, the network architecture, the processes, and the people. It assigns security responsibilities to each stakeholder in the supply chain.

## Formal Definition / Statement
IEC 62443 is a series of international standards for industrial automation and control system (IACS) security. It's organized into four tiers:

**General (1-x)**: Concepts, terminology, and metrics
- 1-1: Concepts and models
- 1-2: Master glossary
- 1-3: System security compliance metrics

**Policies and Procedures (2-x)**: Security management for asset owners and service providers
- 2-1: Security management system for IACS
- 2-4: Security requirements for IACS service providers
- 2-5: Implementation guidance for 2-1

**System (3-x)**: Security architecture and design for system integrators
- 3-2: Security risk assessment and system design
- 3-3: System security requirements and security levels

**Component (4-x)**: Security requirements for component vendors
- 4-1: Secure product development lifecycle
- 4-2: Technical security requirements for IACS components

Security Levels (SL) range from SL 0 (no requirements) to SL 4 (state-sponsored attacker resilience).

## Key Properties / Complexity
- Defines Security Levels (SL 1–4) for both capability and target level
- Zone and conduit model for network segmentation is central to the architecture
- Assigns security responsibilities to four roles: asset owner, system integrator, component manufacturer, service provider
- SL 1: Casual violation (accidental misuse)
- SL 2: Intentional violation using simple means (script kiddie)
- SL 3: Sophisticated attack with moderate resources (organized crime)
- SL 4: State-sponsored attack with extensive resources (nation-state)
- Widely adopted in energy, water, manufacturing, oil & gas sectors
- Required or referenced by many national regulations (EU NIS2, German B3S)

## Worked Example
A water treatment plant upgrades its SCADA system:
1. **Asset owner** (plant operator) performs risk assessment per IEC 62443-3-2
2. They define zones: 'Critical Process' (PLCs controlling chemical dosing) at SL 3, 'Business Network' at SL 1
3. **System integrator** designs conduits (firewalled connections) between zones per 3-3
4. **Component manufacturer** ensures PLCs meet 4-2 SL 3 requirements: authenticated firmware updates, encrypted communications, audit logging
5. The integrated system is verified against the target Security Levels
6. Ongoing management follows 2-1 requirements: incident response, patch management, access reviews

## Common Pitfalls
- **Complexity**: The standard is spread across 14+ documents. Getting started requires significant investment.
- **IT/OT convergence confusion**: Many OT engineers aren't familiar with IT security concepts, and IT security teams don't understand OT constraints (e.g., can't just reboot a PLC during production).
- **Legacy equipment**: Much industrial equipment runs for 15–20 years and can't be updated. IEC 62443-3-2 addresses this through compensating controls, but it's still painful.
- **Certification vs compliance**: True IEC 62443 certification is expensive. Many organizations claim 'compliance' without formal certification.
