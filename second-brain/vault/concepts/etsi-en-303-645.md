## One-line Summary
*A European standard defining 13 provisions for consumer IoT security, forming the basis for the EU Cyber Resilience Act.*

## Core Intuition
Consumer IoT devices (smart speakers, cameras, thermostats) were flooding the market with virtually no security requirements. ETSI EN 303 645 was the first widely adopted standard specifically designed for consumer IoT security. It's pragmatic — focused on the most impactful, achievable security measures rather than comprehensive enterprise-grade requirements. It's also the foundation for the EU's mandatory Cyber Resilience Act.

## Formal Definition / Statement
ETSI EN 303 645 (V2.1.1, 2020) is a European standard providing security provisions for consumer Internet of Things. It defines 13 categories of provisions:

1. **No universal default passwords** — Devices must not ship with default credentials
2. **Implement a means to manage reports of vulnerabilities** — Coordinated disclosure
3. **Keep software updated** — Secure update mechanism, clear support period
4. **Securely store sensitive security parameters** — Credentials, keys in secure storage
5. **Communicate securely** — Encrypt data in transit, use TLS/DTLS
6. **Minimize exposed attack surfaces** — Disable unnecessary services, ports, protocols
7. **Ensure software integrity** — Secure boot, verified updates
8. **Ensure that personal data is secure** — Encryption at rest, data minimization
9. **Make systems resilient to outages** — Graceful degradation, recovery
10. **Examine system telemetry data** — Anomaly detection where appropriate
11. **Make it easy for users to delete user data** — Factory reset that truly erases
12. **Make installation and maintenance of devices easy** — Usable security
13. **Validate input data** — Reject malformed inputs, prevent injection

## Key Properties / Complexity
- Organized as Provisions (mandatory recommendations, not legally binding under EN 303 645 itself)
- Applicable to consumer IoT: wearables, smart home, connected toys, etc.
- Not applicable to medical devices (covered by separate regulations) or automotive
- Forms the technical basis for the EU Cyber Resilience Act (CRA) which makes similar requirements legally binding
- Endorsed by the UK government as the baseline for the UK IoT security label
- Can be used as a basis for conformance assessment and certification

## Worked Example
A smart home camera manufacturer wants to comply with ETSI EN 303 645:
- Provision 1: Replace default 'admin/admin' with a unique per-device password set during first boot
- Provision 3: Implement OTA updates with signed firmware, display end-of-support date
- Provision 4: Store Wi-Fi credentials in encrypted flash, not plaintext
- Provision 6: Disable UPnP and Telnet by default, only open HTTPS management port
- Provision 8: Encrypt stored video footage, allow users to disable cloud recording
- Provision 11: Factory reset must delete all Wi-Fi credentials, user accounts, and stored footage

## Common Pitfalls
- **Not legally binding (yet)**: EN 303 645 is a harmonized standard, not law. The EU CRA will change this.
- **'Should' vs 'Shall'**: Many provisions use 'should' — they're recommendations, not strict requirements. This ambiguity allows weak compliance.
- **Scope confusion**: Only applies to consumer IoT, not industrial or medical. Manufacturers sometimes claim compliance for products outside scope.
- **No enforcement mechanism**: Unlike FIPS 140-2, there's no accredited lab testing requirement. Self-declaration is common.
