3.3(a) three correct processes, delta = 2 h, clocks 03:00 04:00 05:00
==========================================================================
  P1 own=03:00  used=['03:00', '04:00', '05:00']  -> 04:00   kept=[1, 2, 3] replaced=[]
  P2 own=04:00  used=['03:00', '04:00', '05:00']  -> 04:00   kept=[1, 2, 3] replaced=[]
  P3 own=05:00  used=['03:00', '04:00', '05:00']  -> 04:00   kept=[1, 2, 3] replaced=[]
  after one round: ['04:00', '04:00', '04:00']  max pairwise difference 0 h

  Rival reading, 'differing by delta OR MORE' (>=):
  after one round: ['03:20', '04:00', '04:40']  max pairwise difference 80 min -> the strict '>' is what makes the example converge

==========================================================================
3.3(b) P2 malicious: brute-force the two lies that maximise |P1 - P3|
==========================================================================
  P2 -> P1: 01:00   P2 -> P3: 07:00
  P1 becomes 03:00, P3 becomes 05:00
  |P1 - P3| = 120 min = 2 h = 1.0000 * delta
  (both lies sit exactly ON the delta boundary, so both are kept:
   P1 averages 03:00 01:00 05:00 -> stays 03:00, P3 averages
   03:00 07:00 05:00 -> stays 05:00: the round achieves nothing.)

  Why it fails (3.3c): the bound is (3m/n)*delta and convergence needs n > 3m
    n=3 m=0:  3m/n = 0.000  ->  new divergence < 0.000 h   OK (< delta)
    n=3 m=1:  3m/n = 1.000  ->  new divergence < 2.000 h   NO GUARANTEE (>= delta)
    n=4 m=1:  3m/n = 0.750  ->  new divergence < 1.500 h   OK (< delta)
    n=6 m=2:  3m/n = 1.000  ->  new divergence < 2.000 h   NO GUARANTEE (>= delta)
    n=7 m=2:  3m/n = 0.857  ->  new divergence < 1.714 h   OK (< delta)

3.2 CNV simulation  (the sheet's exercise2-cnv.py is NOT in raw/)
==========================================================================
  Nodes hold a clock value in seconds. One round = 1 s of real time.
  A correct node reads every clock with +-0.02 s noise and applies CNV.
  A faulty node may report a different value to every reader.

  1. 4 nodes, perfect, sync step removed               final max-min =  0.0000 s   (stays perfect by construction)
  2. 4 nodes, one +0.8 s offset (< delta), all correct final max-min =  0.0115 s   (peak  0.0216)
  3. 4 nodes, one +8 s offset (> delta): frozen out    final max-min =  8.0122 s   (peak  8.0305)
  4. 4 nodes, one 5 % fast, all correct                final max-min =  0.0115 s   (peak  0.0216)
  5. 4 nodes, 1 malicious (n=4 > 3m=3), correct CNV    final max-min =  0.3949 s   (peak  0.5028)
  6. 3 nodes, 1 malicious (n=3 not > 3m), correct CNV  final max-min =  0.5003 s   (peak  0.6622)
  7. 4 nodes, 1 malicious, naive average (no clamp)    correct nodes agree to  0.0085 s, but the whole group is dragged  1000.0 s off true time

3.4(c) four round-trip measurements -- pick the best, report the offset
==========================================================================
        delta = rtt (s)   theta = offset (s)  server processing (s)
  M1              0.100               -2.500                  0.100
  M2              0.200               -2.450                  0.100
  M3              0.200               -2.550                  0.100
  M4              0.100               -2.500                  0.100

  criterion 1 - smallest delay delta = 0.100 s -> ['M1', 'M4'] tie
  criterion 2 - agreement with the other measurements: theta range over all four = 0.100 s;
                M1 and M4 give theta = -2.500 s, M2 gives -2.450, M3 gives -2.550
  -> select M1 (M4 is identical); estimated offset E = -2.500 s
     residual error bound for that pick: delta/2 = 0.050 s
     M3 rejected: its delay ties M2's but its theta is 0.050 s off the consensus
